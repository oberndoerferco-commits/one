# D. UX — desktop-first, keyboard-first

Design question for every screen: **can the vet spend less time looking at this
and more time looking at the animal?**

---

## 1. Principles

1. **One screen for the whole job.** Patient, notes, draft, review, approve and
   export live in one workspace. No wizard, no page-per-step.
2. **Keyboard is the primary input.** Every action has a shortcut; the mouse is
   optional. Focus is always visible.
3. **Type less, check more.** The vet's effort moves from writing to checking.
   The UI is built to make checking fast: source highlighting, flagged gaps,
   diffs.
4. **Calm.** Neutral palette, one accent colour, no animation beyond ≤ 150 ms
   state transitions, no confetti, no chat bubbles, no "AI sparkle" iconography.
   Status is text, not decoration.
5. **Honest state.** Draft vs approved is unmistakable at a glance (label, colour
   *and* shape; never colour alone). Missing information is shown, not hidden.
6. **Nothing surprising.** AI never changes text the vet edited. Regenerate is
   per-section and shows a diff before replacing.
7. **International by default.** Layout tolerates +40 % string length (German),
   dates/units per clinic locale, no text baked into images.

- **Left rail (collapsible, `[`):** patient header + compact timeline. Clicking a
  past consultation opens it read-only in a split, never replacing the current
  draft.
- **Centre:** notes. Plain monospace-optional textarea; no rich-text toolbar.
- **Right:** the document. Sections in the clinic's order. Hover/focus a
  sentence → its source lines highlight on the left (and vice versa).
- **Footer:** the shortcuts that matter *in this state* (context-sensitive), so
  they are learned without a manual.

At 1024–1279 px the left rail collapses to an icon bar. Below 1024 px notes and
report stack with a toggle; the MVP does not optimise for phones.

## 3. States of a consultation

| State | Label | Visual | Allowed actions |
|---|---|---|---|
| Empty | — | cursor in notes | type, pick template snippet (`/`) |
| Notes, not structured | "Notes" | — | `Ctrl+Enter` structure |
| Draft | **● DRAFT** (amber, filled circle) | DRAFT watermark on preview/PDF | edit, regenerate section, resolve flags, approve |
| Needs attention | **▲ n items** | triangle icons at each flag | Tab cycles; approve allowed only after each *missing* flag is filled or explicitly marked "not recorded" |
| Approved | **✓ APPROVED · Dr. Rossi · 14:32** (green, check) | no watermark | export, generate derived docs, amend |
| Amended | **✓ APPROVED v2** + "view changes" | diff link | as approved |

"Mark as not recorded" is a deliberate, logged choice: the report then says
*"Not recorded"* in that field instead of leaving silence the reader might
misread.

## 4. Key interactions

**Structuring.** `Ctrl+Enter` → section headings appear immediately, text streams
in. The vet can start reading the first section while the rest loads. If they
keep typing notes, a quiet "Notes changed — restructure (Ctrl+Enter)" appears;
nothing re-runs automatically.

**Flags.** Two kinds only, so they stay meaningful:
- **Missing** (▲): needed for this document, not in notes. Inline field to type
  the value; the value goes into the *record* and re-renders everywhere.
- **Check** (?): the AI was unsure how to read something (`"mtz"` – unknown
  abbreviation; `"meloxicam 0.1"` – unit missing). Shows the original text.
  Never auto-resolved.

**Editing.** Click or `Enter` on a section to edit in place. Edits are
attributed (human) in version history. Regenerating a section the vet edited
asks first and shows a diff.

**Approve.** `Ctrl+Shift+Enter`. A compact confirmation lists anything
unresolved and the attestation line ("I have reviewed this AI-assisted document").
No modal for routine approvals with nothing unresolved — just a 5-second
"Undo" toast (undo = revert to draft, logged).

**Derived documents (`D`).** A small menu:

```
Generate from approved record
  1  Owner explanation          [EN ▾]
  2  Home-care & medication     [EN ▾]
  3  Discharge summary          [EN ▾]
  4  Referral letter…           
  5  Client email…
```

Number key selects; language picker remembers the owner's preferred language.
Each document opens as a tab in the right pane with its own draft/approve cycle.

**Export.** `Ctrl+Shift+C` copies a PIMS-friendly plain-text version (no
markdown symbols, clean line breaks, section labels in capitals) — tested
against how common PIMS free-text fields actually paste. `P` = PDF preview,
`Ctrl+P` = print.

## 5. Quick entry helpers (optional, never required)

- **Snippets:** `/` in notes opens clinic snippets (`/vacc`, `/dental`,
  `/castration`) that insert bullet scaffolds, not prose.
- **Header line parsing:** the first line `Luna 6y F Lab 28kg` updates the
  patient header after confirmation.
- **Abbreviation dictionary:** per clinic; the review pane shows expansions so
  the vet sees what was understood.

## 6. Visual language

- Type: one humanist sans for UI (e.g. Inter / Source Sans 3), one readable serif
  optional for printed reports. Base 15–16 px, 1.5 line-height in the document
  pane.
- Colour: neutral greys, one deep teal/blue accent for actions. Semantic colours
  only for state (amber draft, green approved, red blocking error), always paired
  with an icon and a word.
- Density: comfortable, not dashboard-dense; the document pane should look like a
  document.
- Dark mode: supported (night shifts, emergency clinics).

## 7. Accessibility

WCAG 2.2 AA as the floor: full keyboard operation, visible focus, 4.5:1 contrast,
screen-reader labels on every flag and status, respects reduced motion,
zoom to 200 % without loss, no time limits on reading (session timeout warns and
preserves drafts).

## 8. Multilingual

UI language and document language are independent. Per-clinic default; per-owner
preferred language; per-document override. Right-to-left support is designed for
(logical CSS properties) but not tested in MVP.

## 9. What we will test with vets (prototype)

1. Unaided task: find patient → notes → approved report → owner instructions.
   Measure time, errors, clicks.
2. Do vets notice and trust the Missing flags, or find them nagging?
3. Is side-by-side source highlighting used, and does it speed up checking?
4. Does the PIMS copy-paste output land cleanly in *their* system?
5. Shortcut discoverability after 10 minutes without training.
